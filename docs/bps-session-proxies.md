# Excel BPS 移植与验证

## 来源和范围

来源固定为 [`ranxi2001/sub2api` `v2.21.1`](https://github.com/ranxi2001/sub2api/tree/v2.21.1)，提交 `11f250894eab310cbd4508946c44c9e2a3a2eb48`。移植的是现有 ChatGPT OAuth 账号的完整 BPS 转发链路及其会话出口、授权、图片、恢复、模板和自动策略；沿用本站管理员认证、账号并发、计费、Astra/Tibo、首字诊断和品牌。

这不是上游全仓库合并。上游独立的 `AuthConnectionID` 多授权连接管理（Codex / BPS / SIWC 多注册）、SIWC、凭据影子账号、TOTP 轮换、Session 导出和通用质量运维任务系统不在本 PR 的路由体系中。本站使用“主 Codex 凭据 + 一个独立 Excel grant”，支持同一个 grant 按不同会话同时使用不同出口；多 IP 不需要多个授权连接。

## 默认关闭及入口

- **系统设置 → BPS**：总开关、图片输入/中转与容量、默认模板。总开关默认关闭。
- **账号编辑 → Excel / BPS**：协议开关、模型范围、会话代理、403 处理、兼容选项、Astra / 用量自动策略。账号协议与自动策略默认关闭。
- **账号的 Excel 授权**：手动 OAuth 和折叠的密码/TOTP 自动授权。秘密只写入专门的加密存储，管理 API 只返回是否配置，不返回密码、TOTP 或 token。
- **Mihomo 管理**：独立内核/节点池配置。也可选择 IP 管理中的代理池。不会自动把服务器变成多个公网出口，须提供实际节点或代理。

关闭 BPS 总开关时普通 OAuth 使用原生模型映射、目录和调度；不会使用 BPS 冷却、模型别名或自动策略。纯 Excel 凭据不能冒充 Codex 凭据使用。

## 独立授权与自动 worker

手动授权和自动授权都校验账号身份、workspace 与 Excel OAuth client，成功只更新独立 grant，不替换主 Codex 凭据。刷新包含互斥锁、refresh token 轮换、CAS 写入和旧 401 保护。启用 BPS 但尚未取得 grant 时保留原生路线，授权成功后通过调度 outbox 刷新。

自动授权须显式开启、保存密码，并配置持久加密密钥；TOTP 填 Base32 密钥，不能填一次性六位码。总 BPS 开关关闭时不会领取任务。后台在缺少 grant 时排队，也支持手动重新授权已有 grant。失败后间隔至少 15 分钟，同一配置最多自动尝试 3 次；手动重试仍受冷却约束。额外安全验证可能需要手动完成，不保证自动登录成功。

队列持久化到 PostgreSQL，使用账号行锁、唯一活动任务和 `SKIP LOCKED` 领取。完成时检查 worker 所有权、配置 revision、主凭据和 grant 快照、身份、30 分钟期限；并发手动授权或修改配置后，旧结果不能覆盖新状态。服务重启会恢复扫描已有任务，过期任务按失败处理，耗尽重试的账号不会挡住后续账号。

内置运行器下载并校验的是 **ranxi2001/sub2api v2.21.1 的 reauth runtime**，不是本站版本的发布产物。Linux amd64 资产为 `sub2api-reauth_2.21.1_linux_amd64.tar.gz`，已核实 release 提供 SHA256 digest。运行器校验下载摘要、解包范围并自检，运行于 `DATA_DIR/excel-login-worker`，不记录子进程输出。也支持通过 `OPENAI_REAUTH_WORKER_TOKEN` 配置外部兼容 worker；配置 token 不等于 worker 在线。该 token 独立于管理员 JWT / 站内 API Key。

## 同账号、多会话、多出口

开启会话代理后，从 Mihomo 或 IP 管理池按账号、API Key、session/thread 分配出口。同一会话复用出口，不同会话可以并发用不同出口；附件上传和对应生成请求共用出口。匿名请求使用请求级临时身份，不跨用户复用历史。

代理池亲和状态在进程内，受容量和空闲清理限制，多实例之间不共享出口绑定。没有健康出口会明确报错，不静默直连。仅在能证明请求尚未发送时进行受限出口切换；发送后的连接中断、流中断不重放请求。出口失败会影响后续选择，客户端取消不会惩罚出口。

可选 Redis replay/catalog 状态与进程内出口绑定是不同功能。Redis 不可用时要求共享状态的请求明确失败，不能跨用户或跨账号拼接历史。

## 上下文、工具与输出

| 能力 | 实际行为 |
| --- | --- |
| Responses / compact | HTTP 转发；支持 SSE 与非流式，compact 转换为 BPS 的压缩流程，不增加 BPS WebSocket 传输 |
| 完整历史 | 保留展开的消息、函数/自定义工具调用和结果关联；作用域内缓存辅助还原完整工具调用，不凭结果虚构调用 |
| `previous_response_id` / `item_reference` | 上游 BPS 协议包不支持独立引用；必须发送展开历史，不承诺按响应 ID 自动补全 |
| 工具 | 明确声明的函数/自定义工具可用；普通 hosted tools 不触发原生 fallback，强制不可用工具会拒绝；可显式选择省略不支持的工具 |
| 有限工具纠正 | 沿用上游校验和次数限制，保留账号、模型、出口与原操作；不会执行模型生成的传输代码，不无限重试 |
| 加密历史 | 当前加密任务不改写；对特定密文拒绝按上游边界恢复。另有默认关闭的有损省略选项，开启会用提示替代不支持的历史，不保证还原密文内容 |
| JSON / JSON Schema | 输出要求转成指令，最终结果本地校验；校验前不把结构化文本提交给客户端，不等于上游约束解码 |
| 用量与诊断 | 计入纠正/压缩消耗；保留本站首字与完整链路记录。区分真实 HTTP 状态、SSE 终态错误和网关转换错误 |

## 图片输入、生图、编辑

图片输入默认关闭。开启后可用原生附件或临时 HTTPS 中转，限制请求体、图像数量/大小、共享内存预算、并发和磁盘存储。附件模式保留上游每图 20 MiB、每请求图片总量 32 MiB 限制；中转 URL 不可猜测并有 TTL。不会静默丢弃图片。

历史图片超限可选拒绝、提醒或 Codex 自动 compact。自动 compact 需要稳定会话、可验证的历史边界和客户端回传压缩窗口，可能额外消耗模型 token；Redis 检查点不保存完整图片/消息。客户端不满足要求时应手动 compact。

BPS 生图/编辑仅按固定上游实现选择 **`gpt-image-2`**：非流式、PNG、opaque/auto 背景；编辑为单张图片，不带 mask 或需服务器下载的远程图片 URL。模型必须在账号 BPS 模型列表里明确选中；“所有文本模型”不会自动改图片路线。

JPEG、透明背景、流式、多图/mask 编辑等不适用请求保留原生 Codex 路线。BPS 在生成前明确拒绝格式时允许原账号原生 fallback；纯 Excel 凭据没有可用的 Codex 授权时明确拒绝，不把 Excel token 发到 Codex。传输失败或已生成的响应不重放。

## 403、429、模型权限

- 429：未接受生成时允许既有调度器在预算内选择其他账号；已接受/流内 429 只记录并冷却 BPS 后续请求，不重放。不会把 BPS 冷却当作主 Codex 账号冷却。
- 模型权限拒绝：限制对应模型路线，避免整个账号被误关。
- 普通 HTTP 403：按账号明确配置关闭 BPS、移动全部原分组到目标组或退出全部分组。恢复 BPS 不自动还原分组。
- 403 自动恢复：默认关闭，可配置间隔；使用有持久领取保护的实际 BPS nonce 探测。探测成功且原状态未变化才恢复；管理员普通测试不触发自动处置。

## 默认模板与 Astra 自动策略

默认模板是表单模板，保存模板不会启用任何账号。账号表单必须点击应用，再保存；初始设置可单独选择。模板沿用上游 BPS 选项，已保存模板的默认值包含密文省略、403 自动关闭和缓存创建按输入计费，因此应用前界面会展示这些选项。

自动策略独立启用，复用本站已有的 **Astra 原生检测结果**，不重新启用已移除的上游定时测试系统，不使用鹈鹕视觉分数，不改现有 Astra 自动换组。可按连续降智次数、5h/7d 已用额度百分比，选择满足其一或同时满足；可在连续健康后还原原 BPS 设置，或在额度仍高时继续保持。

修改策略后从新观测开始计数；未知结果不累计、不打断，重复样本只计一次。规则只管理自己启用的 BPS，保存开启前/后的字段快照。管理员修改 BPS 或发生 403 自动关闭后不覆盖；关闭规则停止后续动作，不自动撤销当前 BPS 设置。Astra 检测本身须保持启用才会产生新质量观测；额度触发不代替质量检测。
