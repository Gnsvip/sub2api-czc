# Codex 自动授权

## 使用

- 添加账号默认选中第一位的 OpenAI OAuth，再选择「自动授权」。名称可留空，以邮箱命名。
- 在同一页面按 `邮箱----密码----TOTP 密钥` 填写，每行一个，最多 50 个。未开启二次验证时保留最后的分隔符，密钥留空。TOTP 项填写 Base32 密钥，不是六位验证码。
- 所有新账号使用当前选择的分组、代理、并发、优先级等设置。授权和连通验证通过前不可调度。关闭页面不会停止已提交的后台任务。
- 已有同邮箱账号不自动覆盖，进入编辑账号中的「Codex 自动授权」配置、保存或重新授权。授权成功后刷新并关闭编辑窗口；其他修改应先保存。
- 「记住添加设置」默认开启，在当前浏览器按管理员、平台和账号类型保存分组、代理、并发、优先级。下次自动带入仍然有效的选项；可取消或清除。密码、TOTP、Token 和账号名称不写入该存储。

首次授权默认优先 Business/Team 工作区。只有个人工作区时授权成功并简短提示；
多个组织工作区时，在「工作区：优先 Business」中填写工作区 ID，或在账号编辑页补填后重试。
首次偏好不改变重新授权的原工作区优先和个人回退规则，不自动处理上游安全校验。

## 自动恢复边界

「掉授权后自动恢复」独立控制，新配置默认开启；已有设置（包括手动关闭）保持原样，仍可自行关闭。账号必须先保存有效登录资料；关闭时仍可手动启动首次授权。仅普通 Codex OAuth 使用此入口，Excel/BPS、PAT 和 Agent Identity 不混用。

从本次更新开始，账号列表显示「重新授权 N 次」，仅累计已有授权账号通过 Codex 重新授权并成功回写的次数；首次授权、普通 Token 刷新、失败/取消及重复回调不计数。计数保存在账号中，清理任务历史或编辑其他设置不会清零。已有历史不推算补记，首次成功重新授权后从 1 开始显示。

已有账号重新授权完成身份和连通校验后，先用新令牌、原出口做一次 Astra 检测，再提交凭据和调度状态。检测正常才恢复原本允许的调度；降智或检测超时/失败时保留成功授权、累计次数，但暂停调度，分别提示「降智，未恢复调度」或「检测未完成，未恢复调度」，不会因此反复重新登录。管理员原先的手动暂停仍保留。

这次恢复前检测独立于定时检测开关，不修改其开关和间隔、不自动换组，明确结果写入现有 Astra 历史。首次授权、普通 Token 刷新、Excel/BPS 保持原有流程。托管协议授权提交的等待上限至少 60 秒，以容纳连通校验（最多 20 秒）与 Astra 检测（最多 25 秒）；其他 worker 请求不变。

启用后只对已持久化的授权失效状态入队，包括后台账号测试写入的 `Authentication failed (401):`，不因普通网络错误、限额、Cyber 策略或上游停用账号自动登录。数据库筛选与服务层判定一致；管理员暂停调度的账号在恢复成功后仍保持暂停。BPS 总开关关闭不影响普通 Codex 队列。

每次登录使用账号配置的主代理（多代理时列表第一项）和独立临时会话。代理不可用时不退回直连。
后台每 60 秒扫描一次已失效的授权。临时失败后冷却 60 秒，再由下一轮扫描重试；首次失败后
最多额外重试 3 次（合计最多 4 次尝试），仍未成功则停止自动尝试。冷却到期不代表立即开始登录，
还需等待扫描及任务领取，通常距上次失败约 60–120 秒后入队；队列繁忙时可能更久。
手动重试也遵守冷却和单账号任务锁。密码/TOTP 错误、身份不一致、安全验证、额外验证、账号停用
和未知协议错误仍需管理员处理，不自动重试。成功任务重置失败预算；登录配置的实际变更使用新版本预算。

授权结果必须满足：Codex OAuth Client ID、有效令牌、原邮箱/用户/工作区一致，以及一次不使用缓存的模型列表验证。回写时再次检查任务归属、配置版本、原凭据、代理和账号调度状态；旧任务不会覆盖管理员的新修改。不修改分组、模型配置或独立 Excel 授权，不解除其他限流/策略保护。

登录密码和 TOTP 使用现有持久化加密密钥加密保存；管理接口不回显密文或明文，凭据请求体整体排除审计。只有专用内部 worker 认证接口可领取执行所需资料。

## 维护与验证

保留 [ranxi2001/sub2api](https://github.com/ranxi2001/sub2api/tree/701612f6e9f7b697eb36397b9fb49bf7324e56a1) 运行包与有限重试调度；普通 Codex 的密码/TOTP 任务使用应用内嵌的 reauth-web 协议适配层，完成邮箱、密码、2FA、工作区选择和 OAuth Token 交换。运行与诊断说明见 [协议授权说明](codex-protocol-authorization.md)。

迁移 `282_codex_automatic_authorization.sql` 增加独立登录配置和共享任务队列的 profile/状态快照；既有 Excel 任务默认仍为 Excel。自动准备环境使用上游 `v2.22.0` 运行包；Linux amd64 包校验值：`9090add61ebdea7b8d15f2086293be1b3ebb9ef26bf3b3dd2d8af41df85593f7`。

在现有 BPS Actions 工作流验证解析及脱敏、授权身份、代理与缓存、PostgreSQL 并发/回写保护、重试上限、前端偏好和任务状态；运行包自检不执行真实登录。按仓库要求，编译和测试在 GitHub Actions 执行。实际平台的密码登录支持、验证码或安全验证仍需授权后的真实验收，不能把模拟测试当作登录成功。
