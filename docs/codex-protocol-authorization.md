# Codex 协议自动授权

普通 Codex 的 `local_worker` 密码/TOTP 任务使用
[boji1334/reauth-web](https://github.com/boji1334/reauth-web/tree/db8251817fd1baefc83c14c851135fb6078bc001)
的协议登录库，完成邮箱、密码、2FA、工作区选择、PKCE 回调和 Token 交换。
首次授权与掉授权后的自动恢复使用同一执行器。BPS/Excel、SIWC、Session Studio
仍按原有配置执行。

## 使用与工作区

管理员在添加或编辑账号时保存邮箱、密码和 TOTP 密钥；已有自动恢复开关保持原值。
首次授权优先唯一 Business/Team 工作区；多个组织工作区需填写工作区 ID。
手动指定工作区时必须匹配该 ID。重新授权优先恢复原工作区，原工作区不存在时，
只允许回退到明确标识的个人工作区，不选择其他团队。只有个人工作区时显示
“仅个人工作区”。类型无法确定时停止并提示选择工作区，不猜测列表第一项。

自动恢复完成后仍由后端执行连通验证与 Astra 检测：检测正常才恢复调度；降智或
检测未完成继续暂停，重新授权计数仍按原规则累计。首次授权不计入重新授权次数。
协议执行器不修改账号分组、代理、自动检测开关或间隔。

因可恢复认证错误自动暂停的账号，会在暂停时原子记录原来的调度意图；授权成功且
本次 Astra 检测正常后恢复调度。重复 401 不覆盖该标记。管理员单独或批量暂停会
撤销自动恢复调度权限，即使账号已经是暂停状态也生效；授权中的旧回调不能覆盖
这个决定。降智或检测未完成继续暂停。旧版本未记录暂停来源的账号不会被批量启用，
应核对成功授权、最新检测及操作记录后再处理。

后台每 60 秒扫描一次授权失效账号。自动恢复的临时失败冷却 60 秒后，由下一轮扫描入队，
首次失败后最多再重试 3 次（总共最多 4 次尝试）。成功后重置失败次数，进行中的任务不会重复创建。
密码、2FA、身份或额外安全验证问题仍需人工处理；Astra 降智或检测未完成不会触发重新授权。

## 账号过期时间与调度

添加 Codex 账号的手动、自动授权页面均可填写或选择账号过期时间；编辑账号的
自动授权设置中也可修改、延长或清除。按浏览器显示的时区输入，后台按时间戳保存。
该日期是账号业务到期时间，与 OAuth Token 自身的短期有效期不同，不会随刷新令牌变化，
也不会写入“记住添加设置”而被后续新账号继承。

新建 Codex 授权默认到期后继续调用；到期后发生可恢复认证错误（401 等）时停止
自动重新授权。扫描、入队、领取任务与写回令牌均检查日期，排队期间到期也会取消
自动恢复。管理员仍可手动发起授权。延长或清除日期后重新按已有自动恢复开关、
冷却和重试预算处理。未编辑日期时，已有账号的到期暂停设置保持；在自动授权设置中
修改并保存日期会设为到期继续使用，但不会主动启用已暂停的账号。

剩余 24 小时内的 OpenAI OAuth 账号进入临期优先分配。同一分组、原优先级和
能力/线路层级内，新会话及无绑定请求先尝试最早到期的可用账号；同一到期时间沿用
原有排序。日期已过但允许继续使用的账号回到普通调度，不会永久占据临期优先位。
未填写日期、负载未知、已有等待或并发无限制的账号保持普通调度。

临期优先分配使用原并发上限的 80%（向下取整、最少 1）作为软上限。例如 50 并发
先使用至 40；达到后立即尝试其他账号。软上限通过现有 Redis 原子抢槽执行，
跨分组、跨实例共享实际已占用槽位，不依赖可能滞后的负载快照。多代理按每个代理
原并发上限的 80% 抢槽，同时检查合计占用；不会更换授权代理或更改路由方式。
同层级其他账号均无空位时，才按原硬上限尝试临期账号剩余容量。原探测预算和
等待策略保留，不为了等待临期号新增排队。

已有会话、previous_response_id 的续接规则保持，粘性请求仍可使用原硬上限。
原绑定临时满载发生的单次分流不覆盖绑定。高级调度中仍然可用的加权粘性会话
不应用临期强排序；显式设置了上游成本权重时，保留该成本评分策略。普通 HTTP
的低成本优先也保留，临期顺序仅在相同成本层内生效。模型支持、限流、冷却、
Astra、隐私和管理员暂停等资格检查继续执行，不因一次模型限流停用整个账号。
后台原有基础评分仅显示评分因素，临期优先由实际选择次序执行，不再显示虚构加分。

验收使用既有完成请求日志：`schedule_allocation=new/sticky` 区分新分配与续接，
`expiry_mode=preferred/overflow` 区分临期软上限与硬上限兜底；`expiry_candidate_id`
和 `expiry_reason` 记录本次候选中最早到期号及未选原因（如 `soft_limit`、
`load_unknown`、`waiting`、资格拒绝或 `policy_order`）。快照并发单独标为
`expiry_snapshot_concurrency`，不冒充原子抢槽时的实时值。不查询已被上游池过滤掉
的账号，也不记录请求内容、会话标识或额外全量候选列表；复用原日志保留策略。
总请求数包含老会话，不能用于单独证明临期优先分配是否生效。

## 运行环境

- 使用已有固定版本 `2.22.0` Linux amd64 托管运行包中的 Python 3.12 和 curl-cffi 0.15.0。
- 应用将协议脚本、来源说明和 MIT 许可嵌入二进制，按内容摘要解压到
  `DATA_DIR/excel-login-worker/codex-protocol-<摘要>/`，升级时切换到新摘要目录。
- 普通 Codex 不再启动 Cloak、Chromium、Xvfb 或 Node.js，不下载浏览器，
  不读取 `OPENAI_CODEX_BROWSER_EXECUTABLE` 或 Cloak 许可证配置。
- 不改写共享 BPS 运行包。BPS 需要的 Node.js 等组件继续保留。
- 每个任务使用独立会话和子进程，使用账号配置的原代理；代理失败不会换出口或直连。
- 协议总时限 180 秒，外层任务时限 240 秒；完成提交保留至少 60 秒等待连通和 Astra 校验。
  失败、取消、父进程退出均清理该任务的子进程。

## 凭据和诊断

密码、TOTP、令牌仅通过私有管道传递，不写入 argv、环境变量、临时文件或运行日志。
认证请求仅允许受限 HTTPS 目标，每次重定向先检查目标；不访问本地回调端口。
授权状态及 PKCE 回调必须匹配当前任务，身份、客户端、令牌有效期、工作区、配置
revision 和数据库 CAS 校验继续保留。验证码、安全校验或其他人工验证要求会停止
当前自动授权，不把额外验证当成成功。

任务错误使用 `codex_protocol_failed`，仅保存固定阶段、动作、原因、耗时和 HTTP
状态码；不保存上游正文、Cookie、授权链接或请求参数。旧版浏览器任务的诊断仍可读取。

## 验证与发布

复用 `tools/test_openai_oauth_reauth_worker.py` 检查工作区选择、令牌身份绑定、
代理隔离、重定向、TOTP、错误脱敏、子进程清理和其他授权方式不受影响。
GitHub Actions 下载并校验固定运行包，实际导入协议库、启动合成任务，不使用真实凭据。
后台原有任务 CAS、自动恢复计数与 Astra 调度门控回归继续运行。

真实授权及自动恢复需另外在隔离实例验收；合成检查不代表真实登录成功。
发布说明记录本次实际覆盖范围和未覆盖场景。

升级仅切换程序与执行器，无数据迁移。既有登录资料、恢复开关、分组和令牌保留。
旧浏览器缓存和系统配置不由程序自动删除；需要清理时由管理员单独核对。
