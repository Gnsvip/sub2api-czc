# 账号多代理

账号创建、编辑、批量编辑支持选择多个代理。OAuth 认证使用列表中的第一个代理；账号保存后的业务请求由 Redis 在可用代理之间轮询分配。

- 不选代理：保持原来的直连逻辑。
- 选择一个代理：保持原来的 `proxy_id` 和账号级并发槽位逻辑。
- 选择多个代理：每个代理的并发上限等于账号配置的并发数。例如，3 个代理、账号并发 10，最多同时放行 30 个请求。一个代理满额时尝试下一个；全部满额时沿用现有等待或拒绝机制。
- 不改动官方的上游 429 响应、重试或额度行为。

## 一致性

Redis Lua 一次完成代理选择和并发占用，返回的代理 ID 决定请求副本的实际出口。释放函数始终释放该次请求的原槽位。各服务实例共用 Redis，因此并发限制和轮询游标跨实例生效。

HTTP 按请求轮询，不承诺多个 HTTP 请求构成的会话始终使用同一 IP。WebSocket 后续轮次固定原出口，再次占用该出口的槽位；没有容量时沿用现有忙碌响应。共享的调度快照不会被请求修改。已停用或过期的代理不参与新请求分配，代理池不可用或 Redis 出错不会退回直连。

长流请求定期续期原代理的并发名额，释放后不会被续期重新创建。异常退出依靠 Redis TTL 清理；Redis 长时间不可用仍受分布式租约失效的限制。

同一账号不能同时开启原生多代理和 BPS（包括自动 BPS）；保存时提示冲突，运行时也防止重复选路。已有 BPS 账号保持原配置，可继续使用其独立的会话代理功能。

## API 与数据

创建接口使用 `proxy_ids: number[]`；更新和批量更新省略此字段表示不改动，空数组表示清空，一个元素表示回到单代理。继续支持旧客户端的 `proxy_id`：显式修改它会清除多代理绑定。列表与详情返回 `proxy_ids`，运行时列表额外返回 `proxy_pool` 中的代理名称和并发计数，不返回代理认证信息。

备份通过有序 `proxy_keys` 导出并映射到导入站点的代理 ID；缺少任意成员会拒绝该账号的导入。受限管理员修改 `proxy_ids` 仍要求 `accounts.network` 权限，不能与随机或最空闲代理模式混用。

有序绑定存放于 `account_proxies`，迁移文件为 `280_add_account_proxy_pool.sql`。账号、绑定和调度通知在同一事务内保存。复制账号保留代理池，被池中账号使用的代理纳入引用计数，不能作为“未使用代理”删除。

## 参考与验证

实现参考 DeanZFC/sub2api-custom 的分布式代理池提交链（f2d1cda5f 至 182a9ab6d），按本项目的 BPS、权限、调度快照和连接池逻辑适配。原版单代理账号不会自动转为多代理。

验证在 GitHub Actions 执行，覆盖 Redis 原子容量、并发轮询、长流续期、代理池持久化及事务回滚、单代理兼容、权限校验和 WebSocket 出口隔离。正式通过结果记录在 PR 和发布说明。多个代理地址不保证对应不同公网出口，也不增加上游承诺的容量。
