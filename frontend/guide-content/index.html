GET STARTED

先开通，再创建密钥

API Key 是客户端连接 AIFXO 的凭据。已有可用密钥的用户，可以直接进入客户端教程。

注册或登录网站

打开 www.aifxo.com，新用户先注册，老用户直接登录。

兑换并确认开通状态

已有兑换码时，进入左侧「兑换」提交。订阅类型查看「我的订阅」的状态、有效期和额度；余额类型查看仪表盘余额。

进入兑换 ↗查看我的订阅

创建属于自己的 API Key

进入「API 密钥」→「创建密钥」，按用途命名，例如 vscode-dev 或 openclaw-main。选择与你的服务对应的分组后保存。

分组会影响可用模型、额度和价格。找不到对应分组时，先检查订阅是否有效。

复制配置并验证一次请求

找到刚创建的 Key，点击「使用密钥」，选择客户端和操作系统。按页面说明配置并重启客户端，发送一个短问题，再到「使用记录」确认请求模型与费用。

默认展示原教程的双文件兼容模式：config.toml 填模型和地址；auth.json 填密钥。两个文件放在同一个 .codex 目录。

位置：%USERPROFILE%\.codex\config.toml
填写：下方模型、提供商和 API 地址配置。新文件可复制完整代码；已有配置合并同名字段，不要重复添加。

确认模型属于你的 Key 可用目录，保存后再处理下一个文件。

第二个文件：auth.json

位置：%USERPROFILE%\.codex\auth.json
填写：先备份旧文件，按下面的完整 JSON 填写。将 YOUR-API-KEY 替换为自己的本站 Key。保留双引号和大括号。

特别注意：不要添加 "auth_mode": "apikey", 这一行。按本教程的双文件兼容方式，auth.json 只填写下面的 OPENAI_API_KEY 字段，不要混入旧登录字段。

保存后检查扩展名确实为 .json，内容使用英文双引号，最后一项后面不要加逗号。

仅当你选择本站「使用密钥」中的 API Key 模式时使用。此方式只编辑 %USERPROFILE%\.codex\config.toml，将 YOUR-API-KEY 替换为自己的 Key，无需另填 auth.json。

这是另一种认证方式，不要与双文件兼容模式的认证字段混用。

顶层 model_provider、model 放在第一个配置表之前，同名字段和表只保留一份。模板保留最小接入字段；模型目录、图片等附加能力以站内「使用密钥」生成的配置为准。

4. 保存、重启并测试

  1. 确认所选认证方式需要的文件都已保存。
  2. 保存后重新启动客户端。打开 ChatGPT 中的 Codex（或你使用的插件 / CLI），新建任务发送一个短问题。
  3. 打开本站 使用记录，检查对应 Key 是否产生记录，模型是否正确。

下拉框显示“自定义”不等于配置失败。结合客户端当前模型与本站实际使用记录判断。

CONFIGURATION TOOLS

用工具完成配置

AIFXO 配置工具和 CC Switch 二选一即可。开始前关闭需要写入配置的客户端，并保留原配置备份。

AIFXO 配置工具

Windows 新版 1.2.0，左侧切换客户端配置与用量查询。填入本站 Key，选择客户端与模型即可；API 地址已预填为 https://api.aifxo.com/v1。

版本 1.2.0，解压后双击 EXE，无需安装 Python。

配置客户端

  1. 打开工具，填写自己的本站 API Key。已有 AIFXO 的 Codex 配置时，也可展开「配置文件与备份」后点击「读取已有配置」。
  2. 选择目标客户端，默认是 Codex 桌面版 · ChatGPT。
  3. 点击「获取模型」，选取当前 Key 的模型；也支持手动输入。
  4. 先完全关闭目标客户端，再点击「一键配置」。核对弹窗中的文件路径后确认。
  5. 重新启动客户端，发送一个短问题，再到本站使用记录检查。

config.toml 写模型与地址，auth.json 写密钥。工具会先备份，保留会话、项目和权限；需要恢复时，在「配置文件与备份」中点击「恢复备份」。双文件兼容模式不添加 auth_mode。

查询额度与用量

  1. 填入本站 Key，选择左侧「用量与额度」，点击「刷新用量」。无需先点一键配置。
  2. 查看剩余额度或钱包余额、今日和累计费用、请求数、Token 及额度窗口。
  3. 需要自动更新时，勾选「每 5 分钟自动刷新」；关闭工具后停止刷新。

费用优先显示实际扣费；未返回的数据显示 —。更换 Key 后会清空旧数据并关闭自动刷新，点击查询即可刷新新 Key 的结果。

支持哪些客户端？

Codex 桌面版、插件、CLI，以及 OpenCode、OpenClaw 支持写入配置。OpenClaw 的默认模型需在客户端另行选择。

Cherry Studio、Positron、Python / API 提供参数导出，需要手动填写。导出文件不包含真实密钥。Claude Code 请按本教程对应章节配置。

CC Switch

先从 CC Switch 官网下载安装并打开。

从网站一键导入（推荐）

  1. 打开本站「API 密钥」页，找到要使用的 Key。接入 Codex 请选择 GPT 分组的 Key。
  2. 点击该行右侧的「导入到 CCS」，允许浏览器打开 CC Switch。
  3. 在 CC Switch 中确认导入并启用配置，再重启对应客户端。

GPT 分组会直接导入 Codex 配置。旁边的「使用密钥」是查看手动配置的入口。

手动添加 Codex 提供商

  1. 左侧选择 Codex，点击右上角「添加供应商」。已有 AIFXO 配置时，点击该行的编辑图标。
  2. 名称填写 AIFXO；官网链接填写 https://www.aifxo.com/。
  3. 填入自己的本站 API Key。按下图界面，API 请求地址填写 https://api.aifxo.com/v1。
  4. 需要时点击「获取模型列表」，选择当前 Key 可用的模型，保存并启用 AIFXO 配置。
  5. 重启 Codex，发送短消息，再到本站使用记录确认请求。

官网链接用于打开网页，API 请求地址用于调用模型。其他版本若自动补 /v1，避免重复填写；最终请求不能出现 /v1/v1。额度查询可继续看 CC Switch 额度配置。

Chat Completions

适合使用 OpenAI 兼容聊天接口的客户端。它与 Responses 的参数结构不同。

POSThttps://api.aifxo.com/v1/chat/completions

最小请求

先完成Key、模型和共用脚本准备。把以下内容保存为 request.json，再发送请求。

字段填写方式
model当前 Key 对应分组支持的模型 ID。
messages按顺序发送消息；每项包含 role 与 content。
streamfalse 返回 JSON；true 返回 SSE。

怎么看结果？

普通文本读取 choices[0].message.content，同时检查 finish_reason。如果返回 tool_calls，需要处理工具调用；如果因长度限制结束，答案可能不完整。

这里使用 messages，不是 Responses 的 input。多轮对话按原顺序携带历史消息；工具结果中的 tool_call_id 必须对应原工具调用。

BPS 类型线路仅支持 HTTP Responses，不支持本接口。接口兼容不等于所有模型参数都通用。先跑通最小请求，再逐项添加推理、图片或工具参数。

max_tokens必填输出上限；按模型能力设置。
messagesuser / assistant 消息列表。
system可选系统提示，放在顶层；不要使用 system 角色消息。

BPS 类型线路不支持 Messages；其他线路以对应分组的实际能力为准。

读取结果

遍历 content，读取 type:text 条目的 text。检查 stop_reason：end_turn 表示本轮结束，tool_use 表示需要执行工具，max_tokens 表示已到输出上限。

直接发请求使用完整 /v1/messages 地址。在 Claude Code 中填写 Base URL 时使用 https://api.aifxo.com，由客户端拼接路径，避免出现 /v1/v1。

流式输出与错误

边生成边显示。收到响应头、收到文字和完整结束，是三个不同的时间点。

试一次流式请求

先设置API Key 环境变量，将下方 JSON 保存为 UTF-8 的 request.json。命令中的 -N 让 curl 及时显示到达的数据。

怎样判断结束？

协议需要检查
Responses文字增量为 response.output_text.delta；等待 response.completed。response.failed / error 是失败，response.incomplete 是未完整完成；取消也不视作完整成功。
Chat Completions读取 choices[].delta，同时检查错误帧、finish_reason 和 [DONE]。错误帧后也可能出现 [DONE]，不能仅凭它判成功；工具调用结束不等于最终答案已生成。
Messages先检查流内 error；读取 content_block_delta，等到 message_stop，再结合 stop_reason 判断结束、工具请求或输出截断。

HTTP 200 不等于整条请求成功。响应开始后仍可能出现流内错误。没有正常终态就断开，应显示“输出中断”，不要静默当作成功。

程序接入注意三件事

  1. 按 SSE 空行边界组装事件，合并该事件的 data: 行后再解析 JSON；网络数据块不一定是一条完整事件。
  2. 忽略 SSE 注释及心跳，[DONE] 不是 JSON。文字增量到达就刷新界面。created、心跳、工具参数或推理事件，不等于首段用户可见回答。
  3. 断流时保留已显示内容和错误信息；不要把重试的新回答直接接到旧片段后面。重试次数应有限。

排查时记录请求 ID、时间、模型、HTTP 状态和流内错误。费用以本站使用记录为准，不要凭 HTTP 状态推断是否扣费。

工具调用

模型提出调用请求，你的程序校验并执行，再把结果交给模型生成答案。

一次调用分四步

  1. 声明工具名称、用途和参数结构。
  2. 模型返回工具名称、参数及调用 ID。
  3. 程序检查工具和参数，执行允许的操作。
  4. 保留历史及调用 ID，回传结果，取得最终回答。
协议结果怎样关联？
Responsesfunction_call_output.call_id 对应原 function_call.call_id。
Chat Completionstool 消息的 tool_call_id 对应原 tool_calls[].id。
Messagestool_result.tool_use_id 对应原 tool_use.id。

哪些操作需要自己处理？

函数工具由你的应用执行。模型返回一个函数名，并不代表服务器已经替你搜索网页、读文件或运行命令。只允许事先定义的工具，检查参数；流式工具参数要收完整后再解析执行。

TROUBLESHOOTING

遇到问题，先检查这里

先看完整错误内容，再判断是配置、额度还是上游响应。错误码相同，不代表原因一定相同。

接入与配置

401：提示密钥不正确

检查 Key 是否完整、是否已启用，以及实际请求地址是否为 api.aifxo.com。确认修改的是当前系统生效的配置，排除旧环境变量、profile 或登录状态覆盖。

如果错误里显示 api.openai.com，说明请求仍发往官方地址，应先修正提供商与 Base URL，再重启客户端。401 也可能由 Key 失效或用户状态引起，不能只归因于缺少配置文件。

404：接口不存在，或地址出现 /v1/v1

检查客户端是否自动拼接 /v1。Codex 手动示例使用 https://api.aifxo.com/v1；Claude Code 使用根地址 https://api.aifxo.com。

400 Bad Request：应该重新换 Key 吗？

先保留完整错误文本和请求 ID。可能是请求字段、历史对话或当前模型不支持的参数，换 Key 不一定有效。可用新会话发送短消息对比，再联系售后。

403 / 429 / 502 分别先查什么？

403：查看错误中的权限、模型或许可提示。
429：检查额度、并发和速率限制，按提示等待。
502：保留请求时间与 ID，检查是否为暂时性上游异常，避免连续快速重试。

Codex 侧栏没有入口

先打开项目文件夹，确认扩展已启用。通过命令面板搜索 Codex: Open Codex Sidebar；仍没有时，检查编辑器与扩展的兼容版本。

原文提供的 Trae 社区讨论可作历史参考，不建议直接替换新版扩展的 package.json。

下拉列表没有我配置的模型

检查模型 ID 是否属于当前 Key 的可用目录，并确认配置已加载。客户端列表可能来自本地目录或缓存；重启后用实际请求记录核对，不要只看显示名称。

额度与使用

兑换成功，余额却没变化

先确认兑换类型。订阅会显示在「我的订阅」，不一定增加钱包余额。刷新页面检查有效期和状态；仍异常时提供兑换时间与记录，完整兑换码不要公开发送。

模型能回答，但首字很慢

检查对应使用记录的模型、推理强度与首字耗时，保留请求 ID。网络连接、排队、上游推理和客户端渲染都可能影响体感，单看一个总耗时无法定位。

如何保留原来的聊天记录？

先备份配置，保留整个会话数据目录，只合并接入相关字段。不要执行删除 .codex 目录的操作。切换提供商后历史记录是否显示还受客户端版本影响，仅换 Base URL 不能保证所有历史自动迁移。

密钥泄漏了怎么办？

立即在本站禁用或删除泄漏 Key，创建新的 Key 并更新客户端配置。截图或发给售后时遮住完整密钥、登录令牌和 Cookie。
